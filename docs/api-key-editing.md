# API Key 编辑与保存

适用版本：`v1.3.5` 及以后。配置入口：**插件页面 → 多 API 模型路由 → 上游配置**。

## 使用

1. 新增 API 时填写 API Base、API Key 和模型 ID，点击“保存并生效”。
2. 替换 Key 时直接修改输入框，再保存；切换输入框或调整“启用路由”不会漏掉新 Key。
3. 获取模型会使用当前输入的 Key，无需先保存；获取成功不代表配置已经保存。
4. 已有 Key 默认显示为掩码。未编辑掩码，或点击“显示”后未修改明文，保存时沿用原 Key。
5. 取消“启用路由”只让该 API 退出整体自动路由；配置完整的聊天兼容 API 仍保留专属 Provider。

## 旧版缺失 Key 的处理

旧版可能出现“已填写 Key 仍提示无法保存”，或取消路由后保存成功、刷新时条目消失。
原因是 Key 未提交到服务器，配置并不完整。

- 条目仍在：重新填写 Key，确认 API Base 与模型 ID 完整后保存。
- 条目已消失：点击“新增 API”，重新填写完整配置后保存。
- Key 已丢失：从服务商控制台重新获取或生成；插件无法恢复从未保存的 Key。

保存后重新打开页面确认条目仍在且 Key 显示为掩码。使用专属 Provider 的其他插件，
同时核对其选择的上游；页面 `#编号` 是固定槽位号，拖拽只调整调用顺序。

## 修复逻辑

页面为单步撤销维护编辑快照。旧逻辑拿当前输入与可变快照中的 `api_key` 比较，
两者一致就省略提交；快照已包含刚输入的新 Key 时，服务器却没有该 Key。

`canReuseSavedApiKey()` 只允许掩码或未改动的按需揭示值沿用服务器密钥。
保存与获取模型共用该判定，其余明文输入均随请求提交，清空 Key 也会显式提交空值。
启用路由时仍必须有完整的 API Base、Key 和模型 ID。

此次修复不改变配置结构、Provider ID、路由策略或密钥查看权限，无需迁移配置。
回归入口见 [测试说明](../tests/README.md)；版本记录见 [更新日志](../CHANGELOG.md)。
